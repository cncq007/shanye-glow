# 山野拾光 · 个人作品集

图片 + 视频双板块的个人作品展示网站。简洁大气的户外风格，**纯本地文件驱动**：没有数据库、没有登录后台，所有内容都由一个 JS 清单文件控制，改完刷新即生效。支持浅色 / 深色主题，`file://` 双击 `index.html` 即可直接打开。

- **线上地址：<https://shanye-glow.app.workbuddy.host/>**
- 本地位置：`E:\山野拾光\`
- 本地预览：直接双击 `index.html`，或 `python -m http.server 8000` 后打开 `http://localhost:8000`

**两条改内容的路径**

1. **云端改（不需要这台电脑）**：GitHub 网页打开 `assets/data/content.js` → 编辑 → Commit，或直接上传图片到 `assets/img/gallery/`。推送后 EdgeOne 与 GitHub Pages 都会自动重新部署。
2. **本地改（有面板，更省事）**：双击 `维护面板.bat` 改完保存，然后 `git add -A && git commit -m "..." && git push` 推上去。

**必须知道的几条约束**

- **单文件 25MiB 上限**：EdgeOne / Cloudflare Pages 都有这条硬限制。7 条视频已从 4K 母版用两遍编码重压到 19.4–24.2MiB（720p），**以后新增视频务必控制在 25MiB 以内**，工具见 `_tools/recloud_encode.py`。
- **EdgeOne 默认域名不能当稳定入口**：无论选哪个加速区域，平台分配的项目域名在大陆都有访问限制（3 小时预览链接 / 直接 401）。只有绑**自定义域名**才是稳定通道。
- **加速区域必须选「不含中国大陆」**：选含大陆区域后，绑自定义域名需要 ICP 备案；不含大陆区域免备案。
- `_admin/`、`_tools/`、`维护面板.bat` 已写进 `.gitignore`，不进云端仓库。

图片板块由三部分组成（沿用「山河入镜」站的设计语言）：

1. **胶片走马灯** —— 全部作品做成一卷深色胶片横向滚动（齿孔 + 片名），悬停暂停，点击任一帧跳到观片台对应作品
2. **观片台** —— 大图舞台 + 缩略图条：叠化/推移/缩放/柔焦/擦除五种切换轮换，每张带 Ken Burns 缓慢运镜，支持方向键翻页、空格自动播放（带进度细线）、F 全屏
3. **拼贴墙** —— 全部作品按大小错落的编辑感网格排布，悬停浮出标题地点，点击进入灯箱大图浏览

## ★ 后台维护入口（推荐从这里开始）

双击站点根目录的 **`维护面板.bat`**，浏览器会自动打开 `http://127.0.0.1:8777/_admin/admin.html`：

- **站点文案**：站名、首屏大图、统计条、三个板块的标题与说明、关于、联系、页脚
- **照片**：可视化改标题/分类/地点/参数，拖动或↑↓调顺序，删除（连磁盘文件一起清理）
- **添加照片**：选本地文件，或直接填电脑上的完整路径 → 自动转正方向、轻度增强、生成 900px 缩略图 + 2000px 大图、读取光圈/快门/ISO/焦距
- **视频**：填源片完整路径 → 自动压成 720p 并抽封面；改封面抽帧时刻后可一键「重抽封面」
- **联系与备份**：改分类和联系方式；每次保存前自动备份到 `_admin/backups/`，可一键回滚

全部改动点右上角「**保存更改**」才写盘；关掉那个黑窗口服务即停止。首次使用若提示缺依赖，运行 `_admin\安装依赖.bat` 即可。

### 维护面板的工作方式（排障时看这段）

面板 = 一个本地小服务（`_admin/server.py`）负责读写磁盘 + 一个网页（`_admin/admin.html`）负责界面。**那个黑色命令行窗口就是服务本体，关掉它就点不动保存了。**

- **怎么找到已启动的实例**：服务启动时把「端口 + 进程号」写进 `_admin/tmp/panel.lock`。再次双击 `维护面板.bat` 时会先读这个锁，确认进程还活着且端口有人在监听，就直接打开已有面板，不会再起第二个（避免两个实例抢着写 `content.js`）。
- **端口固定从 8777 起**，被占就顺延 8778、8779……实际端口以那个黑窗口里打印的地址为准。
- **保存前自动备份**：每次写 `content.js` 前都会先复制一份到 `_admin/backups/`，面板「联系与备份」页可一键回滚。服务端会拒绝写入不含 `window.SITE_DATA` 的内容，防止把清单文件写坏。
- **日志**：`_admin/logs/panel.log` 记录每次启动、自检结果和保存记录。出问题先看这里。

**踩过的坑（已修，留档免得重犯）**

1. **「点了保存提示失败」** —— 启动脚本原本用 `where python` 找解释器，在这台机器上先找到的是 Windows 应用商店的占位程序 `…\WindowsApps\python.exe`。它不输出任何东西却返回成功，脚本便以为服务已经起来，实际什么都没跑，网页自然连不上本地服务。现在改为**逐个候选路径真的运行一次 `_admin/probe.py`**，只有打印出 `PY3` 才算数，占位程序直接被淘汰。
2. **首次启动要等将近一分钟** —— 这台机器上连接**没有人监听**的 `127.0.0.1` 端口不会立刻被拒绝，而是一直阻塞到超时。原逻辑挨个端口去连，几个空端口就拖出一分钟。现在先判断「进程是否还活着」（`OpenProcess`）和「端口是否有人在听」（试绑一下），都是零点几毫秒，只有确实有人听时才去请求 `/api/ping`。**无实例时判断耗时 0.000s。**
3. **偶尔会起第二个实例** —— 探测 `/api/ping` 时只读了一次网络数据，而 HTTP 响应头和正文可能分成两个 TCP 段到达，读到半截就判断失败，于是又起一个服务。现在改为**循环读到连接结束**再判断。

4. **没连上服务也一直挂着「离线」警告** —— 横幅的显示/隐藏用的是 HTML 的 `hidden` 属性，但它的 CSS 写了 `display: flex`，把 `hidden` 顶掉了，于是横幅永远显示：服务明明连着，页面顶部却还写着「保存需要本地服务在后台运行」。修法是在样式表顶部加一条全局规则 `[hidden] { display: none !important; }`，让 `hidden` 永远生效。

## 目录结构

```
index.html                  页面骨架（由 JS 渲染填充，一般不用动）
维护面板.bat                 ★ 双击启动本地维护面板
assets/
  css/styles.css            设计系统：色板/字号/间距/响应式（换强调色只动 :root）
  js/main.js                胶片走马灯、观片台、拼贴墙、灯箱、筛选、主题切换
  data/content.js           ★ 整站唯一内容源：文案 / 照片清单 / 视频清单
  img/gallery/              作品照片：NNN-t.jpg 缩略图(900px) / NNN-full.jpg 大图(2000px)
  img/favicon.svg           图标
  video/                    视频文件 NNN.mp4(720p) + 同名封面 NNN.jpg
_admin/                     ★ 本地维护面板（页面 + 本地服务 + 备份 + 日志）
_tools/                     批处理与测试工具
```

> `_admin/` 与 `_tools/` 目前会随发布一起上传，但在线上只是普通静态文件——本地服务不会启动，接口访问不到，仅供你自己留档，没有泄密风险。

## 日常改内容 —— 只碰 `assets/data/content.js`

| 想改什么 | 改哪里 |
|---|---|
| 站名 / 首屏大图 / 副标题 | `site.name` / `site.hero`（`hero.image` 填项目内路径） |
| 统计条数字 | `site.stats` |
| 板块标题与描述 | `site.gallery` / `site.video` / `site.about` |
| 联系方式 | `site.contact.links` |
| 照片的标题 / 分类 / 地点 / 参数 | `photos` 数组对应条目 |
| 视频的标题 / 地点 / 时长 | `videos` 数组对应条目 |

改完保存、刷新页面即生效。图片路径必须写**相对项目根目录**的路径（如 `assets/img/gallery/g01-t.jpg`）。

> 照片在数组里的顺序就是观片台播放顺序与拼贴墙排布顺序，想调整叙事节奏直接挪动条目即可。
> `params` / `focal` 填拍摄参数（如 `"1/500s · f/5.6 · ISO 100"` / `"24mm"`），留空则观片台不显示参数行。

# 3. 把标题/分类/地点抄进 content.js 的 photos 数组（w/h 用工具打印的输出尺寸）

**方式 B：手动** —— 用任意工具把图缩成两档（长边 2000 / 900），命名 `gNN-full.jpg`、`gNN-t.jpg` 放进 `assets/img/gallery/`，再在 `content.js` 加一条（`w`/`h` 填真实像素）。

## 新增视频

```bash
# 1. 把源片路径和标题加进 _tools/build_videos720.py 的 EPISODES（编号接续 vNN）
# 2. 跑工具（自动: 截前 120 秒 → 720p H.264 → 生成封面）
#    （build_videos.py 是旧版，出 1080p，已不用）
cd E:\山野拾光\_tools
python build_videos720.py
# 3. 封面若取到不理想的画面，改 EPISODES 里的封面秒数后重跑，或在维护面板里「重抽封面」
# 4. 把标题/地点/时长抄进 content.js 的 videos 数组
```

> 体积提醒：视频已统一为 720p（每段约 25–36MB，共约 186MB），是画质与加载速度的平衡点；航拍画面运动量大，再压会明显糊。视频只在点击后才加载，不影响首屏速度。

## 常见问题

**改了 content.js 页面没变化** —— 强刷（Ctrl+F5）；检查 JS 语法是否写坏（F12 控制台报错会中断整站渲染）。

**照片在拼贴墙/观片台里比例不对** —— `photos` 里的 `w`/`h` 与真实图片不符，改成真实像素值。

**视频点了没反应** —— 确认是 MP4（H.264）编码；`.mov/.avi` 浏览器放不了，先用 build_videos.py 转一遍。

**新增的图片/视频显示 404** —— 路径写错或文件没放进对应目录；发布场景下需重新发布才会上线新文件。

**面板能打开、点保存却失败** —— 说明本地服务没在跑或已断开。看那个黑色窗口是否还开着；关掉的话重新双击 `维护面板.bat`。面板顶部出现黄色「离线」横幅时，按「重新连接」或直接重开面板。细节在 `_admin\logs\panel.log`。

**双击 `维护面板.bat` 一闪就没了** —— 说明没找到可用的 Python 3。按窗口里的提示装一个（安装时勾上 “Add python.exe to PATH”），或手动执行 `"某个python.exe" "_admin\server.py"`。
